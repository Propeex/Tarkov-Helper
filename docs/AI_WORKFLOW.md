# AI 작업 및 배포 워크플로

이 문서는 ChatGPT/AI 에이전트를 사용해 Tarkov-Helper를 수정하고 배포할 때 대화 길이에 의존하지 않고 작업을 이어가기 위한 표준 절차입니다.

## 목표

- ChatGPT가 파일 업로드 없이 GitHub 저장소를 직접 읽고 수정합니다.
- 작업 상태를 대화가 아니라 GitHub 브랜치와 Draft PR에 남깁니다.
- 새 대화에서도 관련 Draft PR만 읽으면 즉시 이어서 작업할 수 있게 합니다.
- 기존 GitHub Actions 빌드·릴리즈 체계를 그대로 활용합니다.

## 1. 새 작업 시작

1. `main` 최신 상태를 확인합니다.
2. `agent/<task-slug>` 브랜치를 만듭니다.
3. 요구사항과 첫 변경이 생기면 Draft PR을 가능한 한 일찍 엽니다.
4. PR 설명에 목적, 현재 상태, 검증 결과, 남은 작업, 인수인계 정보를 기록합니다.

작업이 아직 완성되지 않았더라도 Draft PR을 먼저 만드는 이유는 PR 자체를 영구 체크포인트로 사용하기 위해서입니다.

## 2. 작업 중

의미 있는 단계가 완료될 때마다 다음 중 하나를 갱신합니다.

- Draft PR 설명의 현재 상태
- 검증 결과
- 남은 작업 / 다음 행동
- 중요한 결정 또는 회귀 위험

대화 마지막에만 한꺼번에 정리하지 않습니다. 갑작스러운 컨텍스트 종료에도 마지막 체크포인트가 남아 있어야 합니다.

코드나 설정 변경은 해당 작업 브랜치에만 반영합니다. 관련 없는 리팩터링은 같은 PR에 섞지 않습니다.

## 3. 새 대화에서 이어서 작업

사용자가 진행 중인 Tarkov-Helper 작업을 이어 달라고 하면 다음 순서로 복구합니다.

1. 관련 open Draft PR 검색
2. PR 브랜치와 최신 커밋 확인
3. PR 설명과 최근 댓글 확인
4. GitHub Actions 상태 확인
5. 실패한 검증이 있다면 로그 또는 변경 패치를 확인
6. PR의 `남은 작업 / 다음 행동`부터 작업 재개

이 절차에서는 이전 ChatGPT 대화 원문이 없어도 됩니다.

## 4. 표준 CI

현재 표준 CI는 `.github/workflows/build.yml`입니다.

PR에서 자동으로 다음 단계가 실행됩니다.

- `dotnet restore TarkovHelper.sln`
- Release 구성 전체 솔루션 빌드
- 아이콘 변환 self-test
- deterministic database smoke
- live tarkov.dev external database smoke
- `win-x64` Windows release candidate publish
- `TarkovHelper_JH.zip` 및 SHA256 생성

따라서 ChatGPT 작업의 기본 검증 방식은 PR을 올리고 Actions 결과를 확인하는 것입니다.

## 5. 병합과 배포

1. PR 변경 내용을 최종 검토합니다.
2. Build 계열 필수 검증과 release candidate 생성이 성공했는지 확인합니다.
3. 사용자가 병합을 지시하면 PR을 병합합니다.
4. `main`의 기존 `Publish Release` 자동화를 확인합니다.
5. 이어서 `Verify Published Release`가 실제 배포 자산을 검증했는지 확인합니다.
6. 실패 시 새 임시 수동 배포를 만들지 말고 실패한 기존 파이프라인을 수정합니다.

## 6. 대화 종료 방지 원칙

ChatGPT 대화의 최대 컨텍스트 자체를 없앨 수는 없습니다. 대신 작업 상태를 GitHub에 외부화해 컨텍스트 종료의 영향을 제거합니다.

이를 위해 모든 장기 작업은 최소한 다음 세 가지를 GitHub에 남깁니다.

- 작업 브랜치
- Draft PR
- 최신 인수인계 상태

이 세 가지가 있으면 새 대화는 이전 대화 내용을 복원할 필요 없이 저장소 상태에서 직접 재개할 수 있습니다.

## 7. 사용자 입장에서의 최소 사용법

새 작업:

> 타르코프 헬퍼에서 [원하는 수정] 해줘.

이어가기:

> 타르코프 헬퍼 이어서 작업해줘.

배포까지 진행:

> 검증 끝나면 배포까지 진행해줘.

AI는 해당 요청에 맞춰 GitHub의 현재 브랜치, Draft PR, Actions 및 릴리즈 상태를 기준으로 작업합니다.
